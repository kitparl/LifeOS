# Import Markdown from File (.md Upload)

Add **Import Markdown** across three markdown editors in LifeOS. Users upload a local `.md` file and its raw text is loaded into the current document body — the same workflow common in Obsidian, Typora, and similar tools.

## Modules

1. **Knowledge Notes** — section content (`knowledge-subject.component.ts`, docbar near section title)
2. **Communication → Writing** — writing entry content (`writing-form.component.ts`)
3. **Journal** — main entry content (`journal-form.component.ts`)

## Goal

- User selects a `.md` file from their device.
- The file’s **markdown text** is imported into the active content field.
- The `.md` file is **not** stored as an attachment or separate entity — only the text is imported.
- After import, the user can edit, append, and save normally.

## UX

- Add a small **`+` or upload icon** on the **right side of the title row** (docbar / writer bar), next to existing actions (Edit, Save, ⋯).
- Tooltip: **“Import markdown”** or **“Upload .md”**.
- Click opens a hidden file input: `accept=".md,text/markdown,text/plain"`.
- On file select:
  - Read file as UTF-8 text in the browser (`FileReader` or `file.text()`).
  - If the target field **already has content**, show a confirmation dialog:
    - **Replace** — overwrite with imported text
    - **Append** — add `\n\n` + imported text at the end
    - **Cancel**
  - If the field is empty → import directly (replace).
- After import:
  - Switch to **Edit mode** if currently in read mode (Knowledge Notes).
  - Update the editor (`form` + `CodeWorkspaceComponent` / `KnowledgeNotesEditorComponent`).
  - Mark dirty / enable Save.
  - Do **not** trigger a special save path beyond existing auto-save behavior.

## Scope per Module

| Module | Title row | Content field | Save API |
|--------|-----------|---------------|----------|
| Knowledge Notes | `kn-docbar` section title | `form.controls.content` + editor | existing `updateSection` |
| Writing | form title row | `editorContent` + workspace | `CommunicationService` update |
| Journal | `journal-writer__bar` or title area | main `content` field only | `JournalService` update |

**Journal:** import into **main `content` only** (not gratitude / wins / lessons).

## Implementation Guidelines

- Reuse existing UI patterns: `btn-ghost`, `kn-plus`, `ConfirmService`, Ubuntu-style spacing — **do not redesign**.
- Prefer a **shared utility or small standalone component**, e.g. `shared/markdown/markdown-import.ts` or `MarkdownImportButtonComponent`, used in all three places.
- **No backend change required** — client-side file read only.
- Validate: reject non-text files; max size ~2MB with a clear error message.
- Optional: if filename has no title and section title is empty / “Untitled”, suggest title from first `# Heading` (confirm before applying).
- Preserve existing features: attachments, paste-upload images, read/edit mode, auto-save rules.

## Knowledge Notes Specifics

- Place import control in `kn-docbar__actions` (visible in read and edit mode).
- Wire into `KnowledgeNotesEditorComponent.setContent()` when the editor is mounted.
- Import does **not** create `knowledge_notes_extra` attachments.

## Acceptance Criteria

- [ ] `+` / upload icon appears on the title row in all three modules.
- [ ] Selecting `notes.md` fills the editor with the exact file contents.
- [ ] The `.md` file is not uploaded to the Files API or stored as an attachment.
- [ ] Replace / Append prompt appears when content already exists.
- [ ] User can edit and save imported content normally.
- [ ] Invalid or empty file shows a friendly error.
- [ ] UI matches existing LifeOS style.
- [ ] Unit tests for the shared import helper (replace, append, empty file, encoding).

## Out of Scope

- Importing into multiple journal fields at once
- Batch `.md` import
- Converting non-markdown formats (Word, PDF)
- Storing the source `.md` file on the server

## Constraints

- Do not break existing Knowledge Notes UX (read mode, section complete icons, collapse, search).
- Keep the implementation diff focused and reuse existing patterns where possible.
